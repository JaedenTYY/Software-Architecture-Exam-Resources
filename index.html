Pattern selection

Requirement → problem → pattern → elements/connector → mechanism → QA effect → trade-off.

Never stop at “X is suitable because X is scalable/secure.” Explain the structural mechanism.

Six-part QA scenario

Source → Stimulus → Environment → Artifact → Response → Response Measure.

Stimulus is an event. Response measure must be testable/measurable.

Structures

Module: code/implementation organization.

C&C: runtime interaction.

Allocation: software-to-environment mapping.

Critical reasoning

A pattern or tactic may support a QA; it does not guarantee it. Check shared dependencies, bottlenecks, failure modes, boundaries and measurable criteria.

Utility Tree

Utility → QA → refinement → scenario [Business Value, Architectural Impact].

[H,H] scenarios are strong ASR candidates.

Architecture vs design patterns

Architectural patterns organize system structures. GoF design patterns address class/object-level design. Example: Publish-Subscribe vs Observer.
