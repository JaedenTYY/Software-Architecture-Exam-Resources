Architecture questions can sometimes support more than one defensible answer when the pattern is mapped correctly to the scenario and justified through its mechanism.

## What the answer keys contain

Each answer key covers **every question and sub-question** in its paper and is optimized for open-book use:

- scenario-to-pattern justification,
- enhanced/threatened quality attributes with causal explanation,
- formal six-part QA scenarios,
- Utility Trees with Business Value / Architectural Impact ratings,
- runtime vs design-time quality reasoning,
- architectural views and mappings,
- primary-presentation diagrams in text form,
- architectural notation/documentation answers,
- GoF design-pattern answers and architectural-vs-design-pattern distinctions.

## Suggested exam use

1. Read the question first and attempt to identify the concept without opening the answer.
2. Use the main search engine to verify the likely pattern, quality attribute, framework or design pattern.
3. Open the relevant model answer and cross-check the **mechanism**, not merely the pattern name.
4. Adapt the answer to the exact scenario and mark allocation instead of copying a generic paragraph unchanged.
5. Cross-check reusable definitions and distinctions against [`universal_answers.md`](../../universal_answers.md).

The papers and answer keys are intentionally kept separate from generated practice questions so original past-paper wording remains easy to identify.
